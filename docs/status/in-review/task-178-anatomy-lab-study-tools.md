Reason: closing the tab or switching systems mid-round loses nothing, and one question can never add more than one row.
decision: D-pending (Task 178) The compare view is minimal: a second scene of one other system (never the whole body, which is several models and past the per-model budget), all structures shown, no labels, no picking, following the main camera's position, target and up at most every 50 ms. The second model is loaded in full on every device, so on a phone it doubles the memory the lab uses while it is open; the student opens it on purpose from "compare with…" and "close comparison" disposes it.
decision: D-pending (Task 178) The structure list now ranks with `searchStructures`: an exact name (same words, any order, plurals forgiven) first, then names holding every word of the query, alternative names in `also` included, then any structure whose source id starts with the typed id. Names holding only some of the query's words are not listed (stream B's module ranks them in a third tier; the lab leaves that tier out), because on the whole body a common word such as "of" or "left" alone would list hundreds of structures and the list's paging and counts would lose their meaning. Reason: the ranking Christian approved, with the list staying as short as before.
