status: Issue #746, CSP in the HTTP header (#746): after the build, src/security/cspheader.ts copies every page's Astro `<meta>` policy (script and style hashes pooled) into the Content-Security-Policy line of dist/_headers, so the header enforces default-src, script-src and the rest with no 'unsafe-inline' or 'unsafe-eval', and the theme script that runs before the `<meta>` is covered by its hash. The build fails if pages disagree, a source is unsafe, frame-src is anything but youtube-nocookie, or the line passes Cloudflare's 2,000-character limit. Unit tests check the builder and the built header; a browser test serves a page with the real header and checks the theme script runs (and is blocked without its hash). Needs Christian's approval: security headers.
decision: D-pending (Issue #746) The HTTP Content-Security-Policy header carries the full hash-based policy, generated at build time from Astro's per-page `<meta>` policies; public/_headers keeps only the header-only directives and the `<meta>` stays on each page. Reason: a `<meta>` policy doesn't cover scripts before it, and Astro has no static-header output without an adapter.
