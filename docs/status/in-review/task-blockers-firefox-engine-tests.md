## 25 Nov update: product fixes (Chromium-verified; Firefox proof comes from the release PR #634 run)

Cause shared by items 2, 3 and 4 (home-social): Firefox keeps positions in sixtieths of a pixel and reports boxes through 32-bit floats, so a box that starts on a fraction like 419.4531 reads back a hair off (44 px becomes 43.99998) and a position near x.5 can round either way. Chromium keeps sixty-fourths, so it never shows this. The fix is to make the boxes start on a quarter pixel (exact in both). New spec `tests/e2e/exact-layout.spec.ts` (desktop project, device pixel ratios 1, 2 and 3: 12 tests) fails 12 of 12 before and passes after.

- Item 2 (arrow 43.99998): the arrow's top was 419.453125 (the heading's line was 42 x 1.15 = 48.3 px, and the preview page's title 36.96 px), and its left was fractional below 844 px wide (arrow offset 194.18). Now the platter heading's line is rounded to whole pixels (`round()` in global.css), the arrow offset is rounded to a whole pixel in VialPlatter.astro, the arrow has explicit `min-inline-size`/`min-block-size` from the same token and `flex: none`, and the preview page's title has a whole-pixel line (`.preview-page-title`, minus a quarter pixel so the row sits on x.25, never x.5). Arrow top is now 419.25 at 844 x 390 (was 419.453125); size is exactly 44 x 44 at ratios 1, 2, 3.
- Item 3 (footer height 567.0000610 vs 567.0000305): the panel's own height is 567 in every state; what changed was its distance from the page top (803.6875 before, 332.6875 after scrolling), a fraction that comes from the privacy page's 29.7 px prose lines (18 px x 1.65). Prose paragraphs and list items now use whole-pixel lines (Prose.astro; 30 px, about 1% taller), so the footer starts at 804.25 / 333.25. Also found and fixed: the bold word of the chosen segment widened the slider by about 1.1 px per state (the three segments measured 51.56 or 50.44 px depending on the pick); a hidden bold copy of each word now reserves the width (ThemePicker.astro label `data-text`, global.css), so every segment, the slider and the panel have the same box in all states. The bold word is unchanged.
- Item 4, `home-social.spec.ts:53`: every mark has the same row already (flex, 48 px boxes), so the two "rows" are rounding of one position that sat at y 404.453 near 404.5 once Firefox's sixtieths are added. The preview page's title line made that fraction; with the whole-pixel title minus a quarter the row is at 404.25 (never x.5). The other intermittent items in item 4 (`vial-platter.spec.ts:76`, `:121`, `home-games-carousel.spec.ts:92`, `home-phone-sections.spec.ts:139`) are not touched here.
- Left as is: the real site header is 127.5 px (114.625 on a phone) so pages start on a half or an odd fraction; the real home page may still have fractional rows above its marks. Fixing that means whole-pixel lines in the site header (a needs-christian path) and in the type tokens.

## Item 1 (isMobile in Firefox): for Christian to approve

What Playwright's documentation says (page checked on playwright.dev, `class-browser` and `emulation`, and the same text in the installed playwright-core 1.64.1 types): "Whether the `meta viewport` tag is taken into account and touch events are enabled. isMobile is a part of device, so you don't actually need to set it manually. Defaults to `false`." and for `hasTouch`: "Specifies if viewport supports touch events. Defaults to false." The documentation does not say that Firefox does not support `isMobile`, and does not say that it does. The built-in device list has no Firefox phone, and this repository's playwright.config.ts already says "Firefox has no phone emulation". The library sends `isMobile` to Firefox with the viewport (`Page.setViewportSize` and `Browser.setDefaultViewport`), so the hang at `setViewportSize` is plausible but unproven without a Firefox run. Product code is not involved: the spec's `describe` uses `test.use({ hasTouch: true, isMobile: true })`.
Smallest change I would propose (not made): in `vial-platter.spec.ts` at that describe block, keep `hasTouch: true` for every engine and set `isMobile` only for Chromium and WebKit, for example by reading `browserName` in a `test.beforeEach` that opens its own context, or by moving the Firefox run of that one test to a project without `isMobile`. If Christian prefers the smallest edit and accepts it, a `test.skip(browserName === 'firefox', 'Firefox has no phone emulation')` on that block is the least code, but it is a skip, so it needs his explicit approval.
